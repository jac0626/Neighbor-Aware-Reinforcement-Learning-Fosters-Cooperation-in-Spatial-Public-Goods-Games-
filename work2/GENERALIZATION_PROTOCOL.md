# 工作2泛化开发协议

2026-09-15，在读取本阶段结果之前确定。四类模型共同验证仍在运行；本文件规定下一阶段的环境与比较方法，不包含效果结论。最终留出测试协议在模型冻结后另行确定，种子1000–1029继续保留。

## 研究问题与比较对象

分别检验消息内容、奖励抬高方式、失真持续性、博弈参数、异常比例、系统规模和状态观测是否改变当前结论。工作1原模型和已发表图不作修改。

从四类共同验证的`selection.json`读取完整模型和固定合作评分/学习门控模型各自选中的参数。两个模型此后不随环境重新选型或训练。加入IQL、全局NI κ=0.5、上尾过滤 κ=0.5、合作优先 κ=0.2，共六种方法。其余两个训练结构的比较由共同验证批次承担。

所有运行固定100000步，末段为最后20%；每个条件用216–219四个环境种子，每个种子构成方法间配对。每次仿真从头初始化Q表；一次完整仿真是一个重复。全程与末段合作、真实福利、切换率和NI内部行为均保存，逐次结果全部保留。此阶段是范围探索与开发验证，不宣称最终测试显著性。

## 消息条件

每次开始时无放回抽取floor(ρN)个固定异常发送者。正常发送者始终报告真实动作和综合奖励。异常发送者的真实动作仍由自己的学习规则决定；下表仅作用于NI报告。

| 名称 | 异常发送者报告规则 | 检验问题 |
| --- | --- | --- |
| none | 真实报告，ρ=0 | 干净参照 |
| high_defect | 奖励1，动作D | 训练中已有的持续排序失真 |
| high_only | 奖励1，动作保持真实 | 奖励排序与动作伪造分离 |
| flip_action | 奖励保持真实，动作翻转 | 动作通道单独失真 |
| random_message | 奖励U[0,1)，动作C/D各1/2，每个异常发送者每轮重新抽取 | 非定向随机消息 |
| burst_defect | 以零起始步号t计，t mod 1000 < 500时报告奖励1、动作D，其余轮真实报告 | 固定发送者间歇、同步失真 |
| moderate_defect | 奖励min(1,R真实+0.2)，动作D | 较小幅度的奖励抬高 |
| high_cooperate | 奖励1，动作C | 区分合作报告偏置与真假识别 |

除干净参照外ρ=0.1；L=30、M=2、声誉状态、r∈{4.4,4.8}。共16个条件×六种方法×四个种子=384次仿真。随机消息与高奖励合作报告是失真诊断条件，不预设它们一定降低福利，不能把全部失真类型统称为最坏情况攻击。

`selected_bad_fraction`始终表示选中固定异常**发送者身份**的比例。间歇条件的关闭阶段该发送者会报告真值，高奖励合作条件中报告也可能偶然与真值重合。因此，该指标不等于本轮选中被篡改消息的比例。`active_selected_bad_fraction`只统计产生正幅度NI的事件；门控为0时不计入分母。

## 参数、规模和状态条件

所有条件使用六种方法及216–219四个种子，保持100000步和末20%窗口。

- 参数曲线：L=30、M=2、声誉状态，r∈{3.0,3.6,4.0,4.2,4.6}，分别运行干净与ρ=0.1的high_defect，共10个条件。r=4.4、4.8的对应点直接引用消息批次。
- 异常比例：在r=4.8下增加ρ∈{0.05,0.2,0.3,0.5}的high_defect，共4个条件；ρ=0、0.1引用消息批次。参数与比例合计336次新增仿真。
- 规模：L∈{20,50,100}，r=4.8、M=2、声誉状态，干净与ρ=0.1的high_defect，共6个条件、144次仿真。L=30引用消息批次。方法在同一L内配对；不同L的同整数种子不被解释为逐节点配对。
- 状态与感知：比较“声誉状态/M=1”“自身上一动作状态/M=1”“自身上一动作状态/M=2”，均取r∈{4.4,4.8}和干净/ρ=0.1 high_defect，共12个条件、288次仿真。“声誉状态/M=2”引用消息批次。自身动作状态初值为D；下一状态为本轮实际动作，仍使用2×2个体Q表。

四组共1152次新增仿真。引用其他批次的相同配置时保留其原运行标识和来源，不把同一次运行重复计为新的统计样本。若固定时长下轨迹仍有持续趋势，先在开发种子上延长相应条件，并将延长范围及原因记录后再冻结正式测试。

## 随机数与实现验收

新增随机消息使用SeedSequence的第四个子流。前三个子流继续用于Q初始化、固定异常集合和逐轮动作选择。消息随机流不依赖方法、真实动作或是否最终被参考；每个异常发送者每轮依次抽取奖励和动作两个数。每个独立进程、每次仿真均拥有自己的Generator，不在并行线程间共享。

2026-09-15已核验本机Numba支持传入NumPy Generator：100次交错抽样中，消息序列与NumPy一致，开关消息抽样不改变动作随机流，spawn(4)的前三个子流与spawn(3)一致。依据为[Numba官方文档](https://numba.readthedocs.io/en/stable/reference/numpysupported.html#generator-objects)及本机运行；这项小检查不替代完整引擎回归。

实现后须核对：旧设置与归档引擎的轨迹一致；全部消息类型不改变IQL轨迹；ρ=0时消息类型不改变轨迹；随机消息可重现且正常发送者不被修改；间歇阶段切换与规定步号一致；自身动作状态的TD更新写入正确表项；自身动作状态下IQL不随M变化。新攻击和状态代码在当前共同验证结束后接入主引擎，避免正在执行的源码与档案不一致。

计算开销另用相同条件、单工作进程、预热后随机化执行顺序测量。当前并行开发批次的墙钟时间仅作资源记录，不用于算法速度排名。

工具来源沿用`RESEARCH_PLAN.md`中记录的experimental-design与statistical-analysis技能及其引用。
